## Concept report

### 01 — Actionable incident accordion (selected)

- **Source direction:** expose status, timing, owner, alert policy, redacted
  evidence, and next action in one expanded incident.
- **Strategy:** shallow queue/detail split with a single active disclosure and a
  stable five-tab operator shell.
- **Strengths:** strongest scan-to-diagnosis path; keeps the production database
  failure and its investigation signals in one frame.
- **Risks / implications:** dense facts require strict responsive collapse and
  native disclosure semantics. This became the reusable incident hierarchy.

### 02 — Database dependency topology

- **Source direction:** visualize app/container identity, login/password,
  PgBouncer/tunnel, endpoint, grants, timeout, permission, and stale-credential
  signals as one path.
- **Strategy:** numbered dependency stages beside a route queue.
- **Strengths:** clearest causal DB path and healthy-routing-slot distinction.
- **Risks / implications:** the stage cards are too wide for routine mobile use;
  the production DB tab uses the signal model without copying the full card row.

### 03 — Infrastructure operator console (selected)

- **Source direction:** explain retained host pressure, thresholds, freshness,
  restart counters, and missing per-container detail without new probes.
- **Strategy:** dense resource table plus one selected-hotspot pane.
- **Strengths:** makes thresholds, missing data, and retained evidence explicit;
  avoids inventing container metrics.
- **Risks / implications:** table density needs horizontal discipline. It became
  the infrastructure table and selected-hotspot hierarchy.

### 04 — Reliability analysis (selected)

- **Source direction:** combine service-group SLOs, error budgets, incident
  transitions, recoveries, and Telegram policy.
- **Strategy:** metric strip, SLO table, and chronological incident rail.
- **Strengths:** best longitudinal view and strongest noisy-versus-suppressed
  routing explanation.
- **Risks / implications:** generated iconography is inconsistent; the build
  uses semantic status labels and retained event data instead.

### 05 — Critical journey matrix

- **Source direction:** show enabled E2E tests, effective state, target service,
  freshness, failure streak, evidence, and dispatch investigation.
- **Strategy:** wide matrix with a stable selected-journey inspector below.
- **Strengths:** exposes user impact and intentionally unused journeys without
  conflating them with incidents.
- **Risks / implications:** desktop-first table; the production Journeys tab
  uses the same data contract with a responsive layout.

### 06 — Production command center

- **Source direction:** unify all five monitoring domains while keeping the
  actionable incident primary.
- **Strategy:** five-domain status strip over the incident queue/detail split.
- **Strengths:** compact cross-domain orientation and clear DB incident focus.
- **Risks / implications:** summary cells repeat facts available in tabs; only
  the useful cross-domain totals were retained.

### 07 — Evidence-first split pane

- **Source direction:** optimize keyboard scanning, filters, evidence freshness,
  and long inspection content for dozens of incidents.
- **Strategy:** higher-density queue, filters, and persistent detail pane.
- **Strengths:** strongest large-queue ergonomics and explicit evidence states.
- **Risks / implications:** higher control density than the current incident
  count warrants; native disclosure and evidence states were retained.

### 08 — Mobile incident triage

- **Source direction:** collapse the evidence contract to a narrow operator
  surface without losing alert policy or next action.
- **Strategy:** one-column metric strip, expanded incident, evidence checklist,
  and action/evidence sections.
- **Strengths:** validates reading order and narrow-screen information priority.
- **Risks / implications:** the image is 853 px wide rather than the 390 px proof
  viewport; the real implementation is separately verified at 390 px.

### 09 — Change-correlated timeline

- **Source direction:** reveal recurrence across failures, recoveries, routing
  slots, evidence freshness, and investigations without inventing deployments.
- **Strategy:** multi-row retained-event timeline plus event inspector and group
  summary.
- **Strengths:** strongest recurrence analysis and explicit no-correlation state.
- **Risks / implications:** horizontally expensive and generated event spacing is
  internally inconsistent; retained history powers the production reliability
  view without claiming unavailable deployment correlation.

### 10 — Executive / incident hybrid

- **Source direction:** combine a fast executive read with operator-grade DB
  details, five tabs, and missing/stale states.
- **Strategy:** five-metric strip and broad active-inspection surface.
- **Strengths:** clearest overall status sentence and alert-noise policy summary.
- **Risks / implications:** less efficient than the selected accordion for
  repeated triage; its summary language informed the production overview.
